# Общий VPN для домашней сети (Raspberry Pi)

Устройство по умолчанию: Raspberry Pi (`pi5home`). Команды на этой странице выполняются на Pi, если не сказано иначе.

Подключиться к Pi с другого компьютера: `ssh bliss@192.168.0.118`

## Что это

Проект позволяет нескольким устройствам дома (телефон Android и компьютер `dell`) выходить в интернет через VPN Happ, который работает на Raspberry Pi 5. Трафик этих устройств покидает дом через VPN, без отдельной настройки на каждом устройстве.

**Текущее состояние (2026-11-15):** Pi раздаёт свой VPN компьютеру `dell`, и `dell` использует Pi как шлюз. Когда Happ включён, интернет `dell` выходит через VPN Pi; когда выключен — через роутер. Телефон в сети, но его шлюз пока не подтверждён; см. ниже.

## Устройства и адреса

| Устройство | Имя | IP-адрес | Примечание |
|---|---|---|---|
| Raspberry Pi 5 (**устройство по умолчанию**) | `pi5home` | `192.168.0.118` | Общий VPN-шлюз, проводной LAN (`eth0`); `wlan0` выключен |
| Компьютер | `dell` | `192.168.0.103` | Шлюз — Pi. В старых документах `.105`; живой адрес `.103` |
| Телефон | Android | `192.168.0.185` | Клиент, статический IP. Шлюз не подтверждён |
| Роутер | — | `192.168.0.1` | Шлюз по умолчанию для всей сети |

Адреса VPN-туннеля (появляются, когда Happ включён):
- на Pi: `happ-xray`, `172.19.0.1/30`
- на `dell`: `tun0`, `172.18.0.1/30`

| Часть | Статус |

| Видеть, включён ли Happ (по переключателю в приложении Happ) | Сделано. Наблюдатель запускается при каждом включении Pi и следит за вашим выбором |
| Раздать VPN Pi компьютеру `dell` | Сделано (2026-11-14). `dell` выходит через Happ на Pi |

| Безопасный отказ, если правило не удалось применить | Сделано. Контроллер переходит в блокировку, а не в обычный путь |

## Как учитывается выбор «включено / выключено»

Pi видит процесс VPN, но не видит, **хотите ли вы** его включить. Наблюдатель читает управляющие сообщения ON/OFF из GUI Happ и публикует намерение в `/run/vpn-gateway/state.json`. Контроллер следует ему:

- Happ включён и туннель поднят: трафик клиентов идёт через VPN.
- Happ выключен (достоверно observed): трафик клиентов идёт через роутер.
- Состояние отсутствует, устарело, неизвестно или противоречиво: клиенты заблокированы.

Если новое правило не удалось применить, контроллер переходит в **блокировку**, а не оставляет обычный путь. Он никогда не очищает глобальный набор правил nftables и не включает `nftables.service`.

## Что нужно сделать вам

1. **Шлюз телефона (Android).** Телефон в сети, но за 2 минуты наблюдения Pi не увидел от него ARP или DHCP. Старый «выключатель» на `dell` удалён, поэтому если шлюз телефона — `dell`, его трафик теперь доходит до Pi. Если шлюз — роутер, укажите в настройках Wi-Fi телефона шлюз `192.168.0.118`. Затем сравните публичный IP телефона с IP Pi: выполните `curl -s https://api.ipify.org` на Pi и откройте тот же адрес в браузере телефона. Адреса должны совпасть.
2. **Happ на компьютере `dell`.** Нужен ли он вам? Если нет, его удалить или оставить? Пока вы не ответите, на `dell` ничего не меняется.
3. **Проверка выключенного Happ.** Когда удобно, выключите Happ в GUI и убедитесь, что `dell` по-прежнему в интернете через роутер (контроллер должен показать `ORDINARY`).

## Установка на новое устройство (Raspberry Pi)

Одна команда. Она спросит пароль sudo один раз:

```bash
git clone https://github.com/bayunderground/setup-vpn-gateway.git ~/setup-vpn-gateway && bash ~/setup-vpn-gateway/scripts/new-host-setup.sh
```

Скрипт ставит пакеты (включая `strace`), отключает nftables, проверяет Happ, обновляет проект, ставит правило sudo для проверок без пароля, запускает наблюдатель за Happ при каждом включении Pi, устанавливает контроллер пересылки (только проектная таблица `ip vpn_gateway`) и включает IPv4-пересылку через `/etc/sysctl.d/90-vpn-gateway.conf`. Контроллер следует за GUI Happ: ON -> VPN_EXIT, OFF -> ORDINARY, неизвестно -> BLOCK. Отчёт пишется в `/var/log/vpn-gateway/boot-baseline.log`. Удалить всё, что добавил скрипт: `bash ~/setup-vpn-gateway/scripts/new-host-setup.sh --uninstall` (удаляются юниты, проектная таблица и файл sysctl; IPv4-пересылка остаётся включённой до следующей загрузки).

Happ устанавливается отдельно, своим установщиком. Скрипт скажет, если Happ не найден.

## Правила безопасности

- Не запускайте `happ-diag --repair`: команда перезапускает Happ.
- Не включайте `nftables.service` на Pi: его настройки стирают все правила файрвола.
- Не удаляйте сетевые правила без проверки и одобрения.
- Если состояние VPN неясно, считайте, что он **выключен и заблокирован**.
